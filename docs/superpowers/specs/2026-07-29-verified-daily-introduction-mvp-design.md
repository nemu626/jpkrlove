# jpkrlove 인증 기반 데일리 소개 MVP 설계

- 상태: 승인됨
- 작성일: 2026-07-29
- 대상: 첫 iOS/Android 클로즈드 베타와 정식 출시 초기 모델
- 기준 문서: `docs/product-planning.md`, `DESIGN.MD`, `FRONTEND.MD`, `BACKEND.MD`, `ARCHITECTURE.MD`

이 문서와 기존 기준 문서의 MVP 동작이 충돌하면 이 문서의 승인된 결정이 우선한다. 기존 기준 문서의 정합성 수정 항목은 16절에 명시한다.

## 1. 목적

jpkrlove는 본인 확인을 완료한 일본 여성과 한국 남성이 언어와 문화의 장벽을 넘어 결혼을 고려한 관계를 시작할 수 있도록 돕는 제한형 소개 서비스다.

이 설계의 핵심은 다음 두 가지다.

1. 일반적인 데이팅 앱보다 신뢰할 수 있는 상대를 제공한다.
2. 번역과 한일 관계에 필요한 프로필 정보를 통해 실제 대화 시작을 돕는다.

서비스는 결혼상담소처럼 모든 과정을 담당하지 않는다. 사용자가 직접 의사를 결정하고, 운영자는 본인 확인, 프로필 심사, 안전 대응, 소수의 운영 추천에만 개입하는 경량 하이브리드 모델을 사용한다.

## 3. 타깃과 참여 조건

초기 타깃은 다음 조건을 만족하는 사용자다.

- 일본 여성 또는 한국 남성이다.
- 28~39세를 중심으로 모집한다.
- 도쿄권 또는 서울권에 거주한다.
- 한일 국제결혼을 현실적으로 고려한다.
- 상대 국가 방문, 언어 학습, 장래 거주 국가를 논의할 의사가 있다.
- 공적 신분증과 얼굴 대조를 통한 본인 확인에 동의한다.
- 결혼 의향, 자녀 계획, 흡연, 거주 계획을 프로필에 표시하는 데 동의한다.

본인 확인 배지는 본인, 만 18세 이상, 국적이 확인되었다는 의미만 가진다. 독신 여부, 직업, 소득, 인격, 결혼 의향의 진실성까지 보증하지 않는다.

서비스의 성별은 사용자가 직접 설정한다. 본인 확인 배지는 법적 성별을 확인하거나 보증하지 않는다. 초기 모집과 추천은 자신을 여성으로 설정한 일본 사용자와 자신을 남성으로 설정한 한국 사용자를 대상으로 한다.

## 4. 클로즈드 베타와 사업 모델

### 4.1 베타 모집

베타는 초대제로 운영한다. 커뮤니티별 초대 코드를 발급하고, 일본 여성과 한국 남성의 승인 인원을 별도로 관리한다. 한쪽이 과도하게 많아지면 해당 사용자는 대기 목록으로 이동한다.

전체 100명을 동시에 공개하지 않는다.

1. 일본 여성 25명과 한국 남성 25명을 먼저 공개한다.
2. 활동률, 추천 후보 수, 운영 부하를 확인한다.
3. 문제가 없으면 남은 사용자를 양쪽 25명 단위로 추가한다.

### 4.2 정식 과금

베타는 무료다. 정식 출시에서는 본인 확인과 프로필 심사 후 14일 동안 전체 기능을 체험할 수 있다. 체험 기간이 끝났을 때 월 구독이 없으면 프로필을 비공개로 전환한다.

일본과 한국의 기능 및 권한 구조는 동일하다. 현지 통화, 세금, 앱 스토어 가격 단계, 구매력에 따른 금액 조정만 허용한다.

월 구독 가격은 2,000~3,500엔 상당을 목표로 한다. 이 가격을 유지하기 위해 월 구독에 개인 상담, 프로필 첨삭, 교제 코칭을 포함하지 않는다.

### 4.3 주요 비용과 사업 목표

주요 변동 비용은 본인 확인, 요청형 번역, 앱 스토어 수수료, 고객 지원, 안전 대응이다.

정식 출시 초기 목표는 다음과 같다.

- 변동비 차감 후 한계이익률 60% 이상
- 커뮤니티 제휴 중심의 고객 획득 비용 회수 기간 3개월 이내
- 활동 회원 1명당 월간 수동 운영 시간 20분 이내

## 5. 사용자 흐름

### 5.1 초대와 등록

사용자는 제휴 커뮤니티의 초대 코드로 등록한다. 초대 자격이 없거나 해당 그룹의 공개 인원이 초과되면 대기 목록 상태가 된다.

### 5.2 본인 확인

사용자는 공적 신분증, 얼굴 대조, 생존 확인을 제출한다. 확인 완료 전에도 프로필 초안을 작성할 수 있지만 다른 프로필을 볼 수 없고 자신의 프로필도 공개되지 않는다.

### 5.3 프로필 작성과 심사

필수 항목을 작성하고 사진을 제출한다. 운영자는 사진, 금지 표현, 외부 연락처, 필수 항목 누락을 확인한다.

심사 결과는 다음 중 하나다.

- `승인`: 추천 풀에 참여할 수 있다.
- `수정 요청`: 구체적인 수정 이유와 함께 재제출할 수 있다.
- `거부`: 서비스 참여가 허용되지 않는다.

### 5.4 데일리 추천

매일 오전 8시에 최대 5명의 후보를 추가한다. 사용자는 각 후보에 대해 `대화해 보고 싶어요` 또는 `이번에는 넘길게요`를 선택한다.

미확인 추천은 최대 10명까지만 유지한다. 조건에 맞는 후보가 부족하면 0~2명만 표시할 수 있으며, 부적합한 후보로 숫자를 채우지 않는다.

### 5.5 매칭과 메시지

양쪽이 모두 `대화해 보고 싶어요`를 선택하면 매칭과 대화를 한 번만 생성한다. 매칭 전 자유문 전송은 허용하지 않는다.

매칭 후에는 텍스트 메시지를 보낼 수 있다. 사용자가 특정 메시지에서 `번역하기`를 선택했을 때만 번역을 실행한다.

한쪽의 의사 표시는 상대가 자신의 결정을 완료하기 전에 알림, 받은 관심 목록, 프로필 표시로 공개하지 않는다. 쌍방 의사가 일치한 경우에만 매칭 사실을 양쪽에 알린다.

### 5.6 차단, 신고, 매칭 해제

사용자는 언제든 차단, 신고, 매칭 해제를 할 수 있다. 차단은 즉시 양방향으로 적용되며 추천, 신규 메시지, 상대 프로필 접근을 중지한다.

## 6. 추천과 매칭 규칙

### 6.1 필수 적격 조건

추천 후보는 다음 조건을 모두 만족해야 한다.

- 양쪽 모두 본인 확인과 프로필 심사를 완료했다.
- 베타 참여 자격 또는 월 구독이 유효하다.
- 서로의 희망 연령 범위에 포함된다.
- 현재 거주지와 희망 거주 국가 조건이 모순되지 않는다.
- 차단, 이용 제한, 기존 매칭 관계가 없다.
- 과거에 같은 상대와 매칭한 적이 없다.
- 어느 한쪽도 상대를 명시적으로 넘기지 않았다.

### 6.2 순위 요소

필수 조건을 통과한 후보는 다음 순서의 요소로 정렬한다.

1. 결혼 희망 시기의 유사성
2. 자녀에 관한 희망의 일치
3. 흡연 조건의 일치
4. 희망 거주 국가와 이주 의사
5. 언어 수준과 학습 의사
6. 최근 활동 상태
7. 추천 노출 횟수의 공정성

받은 관심 수와 인기도는 순위에 사용하지 않는다. 사용자에게 근거가 불명확한 궁합 점수도 표시하지 않는다.

### 6.3 의사 표시 수명

`대화해 보고 싶어요`는 30일 동안 유효하다. 이 기간 안에 상대도 같은 의사를 표시하면 매칭된다. 기간이 끝난 후보는 나중에 다시 추천될 수 있다.

`이번에는 넘길게요`를 선택한 후보는 원칙적으로 다시 표시하지 않는다.

### 6.4 운영 추천

운영 추천은 회원 1명당 주 1건까지다. 운영자는 필수 적격 조건을 완화할 수 없으며, 추천 이유만 추가할 수 있다. 추천 담당자는 비공개 메시지를 볼 수 없다.

## 7. 프로필과 공개 범위

### 7.1 공개 정보

- 닉네임 또는 성을 제외한 이름
- 나이
- 국적
- 도도부현 또는 광역 도시
- 사진 2~6장
- 자기소개
- 결혼 희망 시기
- 희망 거주 국가와 이주 의사
- 자녀에 관한 희망
- 흡연 여부
- 일본어와 한국어 수준
- 상대 언어 학습 의사
- 선택적인 직업 분류
- 본인 확인 완료 표시

메인 사진은 본인의 얼굴을 명확하게 확인할 수 있어야 한다.

### 7.2 비공개 정보

- 법적 이름
- 생년월일
- 신분증 이미지
- 얼굴 대조 데이터
- 정확한 주소
- 전화번호
- 이메일 주소

MVP에서는 정확한 직장, 연봉, 가족관계 서류를 수집하지 않는다.

### 7.3 매칭 전용 정보

희망 연령 범위와 추천 제외 조건은 추천 계산에 사용하지만 다른 회원에게 직접 공개하지 않는다. 공개 프로필의 결혼 시기, 자녀, 흡연, 거주 계획을 필수 조건으로 사용할지는 사용자가 각 항목에서 명시적으로 설정한다.

## 8. 메시지와 번역

### 8.1 메시지

- 텍스트만 지원한다.
- 한 메시지는 최대 1,000자다.
- 이미지, 영상, 음성, 파일을 지원하지 않는다.
- 읽음 표시, 입력 중 표시, 마지막 접속 시각을 제공하지 않는다.
- 메시지 편집과 상대 화면에서의 삭제를 제공하지 않는다.

송신 직전에 활성 매칭과 차단 상태를 서버에서 다시 확인한다. 서버 저장이 완료된 뒤에만 `전송됨`으로 표시한다. 네트워크 오류 시 `전송 실패` 상태와 멱등한 재전송을 제공한다.

### 8.2 번역

사용자가 `번역하기`를 선택한 메시지만 번역 사업자에게 보낸다. 번역 결과는 원문과 별도 저장하고 재사용한다.

번역문에는 기계 번역임을 표시한다. 사용자는 원문과 번역문을 전환할 수 있고 오역을 신고할 수 있다. 번역 장애가 원문 메시지의 송수신을 막아서는 안 된다.

외부 번역 사업자로 원문이 전송된다는 사실과 처리 목적을 가입 과정에서 안내한다. 첫 번역 요청에서도 이를 짧게 다시 확인한다.

### 8.3 외부 연락처

전화번호, LINE, KakaoTalk, URL을 일괄 차단하지 않는다. 처음 외부 연락처를 공유하려는 시점에 금전 요구, 외부 유도, 성급한 개인정보 공유에 관한 안전 안내를 양쪽에 표시한다.

### 8.4 알림

푸시 알림에 메시지 본문과 민감 정보를 포함하지 않는다. `새 메시지가 있습니다`와 같은 일반 문구를 사용한다.

## 9. 안전과 운영

### 9.1 메시지 개인정보

일반 메시지는 운영자에게 공개하지 않는다. 신고자는 대상 메시지를 명시적으로 선택해 증거로 제출한다.

운영자는 안전 사건 조사에 필요한 범위에서만 제출된 증거를 확인한다. 추천 담당자와 일반 고객 지원 담당자는 메시지 증거에 접근할 수 없다.

### 9.2 신고 분류

- 사칭
- 기혼 의심
- 금전 요구 또는 사기
- 괴롭힘
- 성적 콘텐츠
- 차별 또는 협박
- 연령 위반
- 기타

### 9.3 운영 조치

- `주의`
- `일시 비공개`
- `이용 정지`
- `영구 정지`

영구 정지는 원칙적으로 복수 담당자 또는 책임자의 확인이 필요하다. 긴급 상황에서는 먼저 일시 정지할 수 있다. 조치 사유와 운영 작업은 감사 로그에 기록하고 사용자에게 이의 신청 경로를 제공한다.

### 9.4 비내용 기반 제한

운영자는 전체 메시지 내용을 상시 검사하지 않는다. 전송 빈도, 같은 문장의 대량 전송, 외부 연락처의 반복 전송과 같은 메타데이터를 사용해 스팸을 제한할 수 있다.

### 9.5 계정 제어

사용자는 프로필 공개를 일시 정지하고 다시 시작할 수 있다. 일시 정지 중에는 신규 추천과 의사 표시를 받지 않지만 기존 대화는 사용자가 별도로 매칭을 해제하거나 차단하기 전까지 유지한다.

사용자는 데이터 내보내기와 계정 삭제를 요청할 수 있다. 정식 구독 취소 시 이미 결제한 기간까지 기능을 유지하고 다음 갱신부터 청구하지 않는다. 계정 삭제는 안전 사건과 법적 보존 대상 데이터를 제외하고 외부 공급자까지 정합성을 맞춰 처리한다.

## 10. 시스템 모듈과 데이터 흐름

기술 기준은 Expo/React Native 모바일 앱, Next.js 운영 앱, Supabase/PostgreSQL 모듈형 모놀리스다.

| 모듈 | 책임 |
| --- | --- |
| Invitation | 초대 코드, 그룹별 인원 제한, 대기 목록 |
| Identity | 본인 확인 세션, 결과, 만료, 재확인 |
| Profile | 공개 정보, 비공개 조건, 사진, 운영 심사 |
| Recommendation | 적격성, 순위, 일일 배치, 운영 추천 |
| Matching | 의사 표시, 유효기간, 상호 매칭, 해제 |
| Messaging | 대화, 원문 메시지, 전송 상태 |
| Translation | 번역 요청, 결과, 오역 신고 |
| Safety | 차단, 신고 증거, 운영 조치, 이의 신청, 감사 |
| Membership | 베타 자격, 무료 체험, 월 구독 권한 |
| Analytics | 개인정보를 제외한 퍼널과 E1 이벤트 |

Cron이 일일 추천 생성을 시작한다. Recommendation 모듈은 적격 후보를 계산하고 각 결과에 규칙 버전과 추천 이유를 저장한다.

Matching 모듈은 쌍방 의사를 확인하고 하나의 트랜잭션으로 매칭과 대화를 생성한다.

Messaging 모듈은 원문을 먼저 저장한다. 명시적 번역 요청만 비동기 Translation 처리로 전달하며 결과를 별도 레코드로 저장한다.

운영 앱은 service-role 자격 증명을 브라우저에 전달하지 않는다. 서버의 제한 API를 사용하고 역할별로 접근을 제어하며 모든 민감 작업을 감사한다.

## 11. 오류와 예외 처리

| 상황 | 동작 |
| --- | --- |
| 추천 후보 없음 | 조건을 완화하지 않고 다음 갱신을 안내 |
| 매칭 동시 처리 | 고유한 매칭과 대화를 하나만 생성 |
| 메시지 전송 실패 | 실패 상태와 중복 없는 재전송 제공 |
| 번역 사업자 장애 | 원문을 유지하고 나중에 재시도 |
| 차단 또는 이용 정지 | 송신 직전에 재검증해 거부 |
| 본인 확인 만료 | 프로필을 비공개로 바꾸고 재확인 안내 |
| 본인 확인 공급자 장애 | 제출 상태를 보존하고 공개하지 않은 채 재시도 안내 |
| 초대 인원 초과 | 계정을 대기 목록으로 이동 |
| 프로필 심사 실패 | 구체적인 수정 이유와 재제출 경로 제공 |

## 12. 측정과 베타 판정

### 12.1 North Star Metric

North Star Metric은 다음과 같다.

> 본인 확인 완료 후 14일 이내에 상호 매칭하고, 양쪽이 각각 3통 이상 메시지를 보낸 사용자의 비율

일본 여성과 한국 남성의 결과를 반드시 별도로 계산한다.

### 12.2 보조 이벤트

- 초대 수락
- 본인 확인 완료
- 프로필 공개
- 추천 표시
- 의사 표시
- 매칭
- 첫 메시지
- 양쪽 3통 도달
- 매칭 후 7일 대화 지속

분석 이벤트에 메시지 본문, 번역문, 신분증 정보, 정확한 생년월일을 포함하지 않는다.

### 12.3 8주 베타 일정

| 기간 | 활동 |
| --- | --- |
| 1~2주 | 초대, 본인 확인, 프로필 심사 |
| 3~6주 | 추천, 매칭, 메시지 이용 |
| 7주 | 가격 표시 테스트와 지불 의사 조사 |
| 8주 | 일본과 한국 사용자 인터뷰, 계속 여부 판단 |

### 12.4 목표

| 지표 | 목표 |
| --- | --- |
| 초대 후 본인 확인 완료 | 60% 이상 |
| 본인 확인 후 프로필 공개 | 80% 이상 |
| 주간 추천 확인 | 70% 이상 |
| 14일 내 유의미한 대화 시작 | 양쪽 모두 25% 이상 |
| 양쪽 대화 시작률 차이 | 10%포인트 이내 |
| 매칭 후 7일 대화 지속 | 30% 이상 |
| 월 2,000~3,500엔 상당 지불 의사 | 30% 이상 |
| 수동 운영 시간 | 활동 회원 1명당 월 20분 이내 |

한쪽만 목표를 달성하면 성공으로 판단하지 않는다. 양쪽이 미달하면 기능을 추가하기 전에 타깃, 후보 수, 추천 규칙, 프로필 품질을 검토한다.

## 13. 테스트와 출시 조건

### 13.1 필수 테스트

- 추천 적격 조건, 넘김 제외, 30일 유효기간, 노출 공정성의 도메인 테스트
- 비공개 프로필, 신분증, 신고 증거, 메시지에 관한 RLS 거부 테스트

- 긴급 이용 정지

### 13.3 베타 출시 조건

- 신고와 안전 대응 담당자 확정

- 본인 확인 문서, 신고 증거, 메시지, 탈퇴 계정의 보존 기간에 관한 개인정보·법률 검토 완료

## 15. 구현 분할 원칙

이 문서는 전체 MVP의 공통 제품 기준이다. 구현 계획은 다음 순서의 독립적인 작업 묶음으로 분할한다.

1. 계정, 초대, 본인 확인, 프로필과 운영 심사
2. 추천, 의사 표시, 매칭
3. 메시지, 요청형 번역, 차단과 신고
4. 운영 앱, 분석, 베타 자격과 정식 구독

각 작업 묶음은 이 문서의 공개 범위, 권한 경계, 상태 전이를 변경할 수 없다. 변경이 필요하면 구현 전에 제품 설계를 다시 승인받는다.

## 16. 기존 기준 문서 정합성 수정

구현 계획의 첫 문서 작업에서 다음 차이를 반영한다.

- `DESIGN.MD`의 최소 프로필 사진 수를 1장에서 2장으로 변경한다.
- `DESIGN.MD`에 일본 여성 50명과 한국 남성 50명의 초대제 초기 타깃을 반영한다.
- `DESIGN.MD`의 받은 관심 메뉴를 제거하고, 한쪽 의사 표시를 상호 결정 전까지 숨기는 흐름으로 변경한다.
- `BACKEND.MD`의 메시지 전송 시 자동 번역 큐 등록을 제거하고, 명시적 번역 요청 시에만 큐에 등록하도록 변경한다.
- `ARCHITECTURE.MD`의 번역 데이터 흐름을 명시적 사용자 요청 방식으로 구체화한다.
- `docs/product-planning.md`의 무료 탐색과 프리미엄 상담은 장기 가설로 구분하고, 정식 출시 초기 모델을 14일 체험 후 월 구독으로 명시한다.

이 정합성 수정은 승인된 제품 동작을 바꾸는 작업이 아니라 기존 문서를 본 설계에 맞추는 작업이다.
